# Investigation

Read-only. Cited explanation or recommendation — no code change.

1. Gather evidence from code, history, and runtime as needed.
2. How-questions → Overview / Key concepts / How it works / Where things live / Gotchas.
3. Why-questions → separate recorded intent from inference; cite sources.
4. Decision requests → short tradeoffs table + clear recommendation.
5. Worklist checkpoint: `n/a, read-only investigation`.
6. Unslop the reply.

If investigation precedes implementation, hand back and re-route to bug-fix or feature.
